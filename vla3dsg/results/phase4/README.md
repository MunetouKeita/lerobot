# Phase 4: 追加学習なしの結果の分析

- 日時: 2026-10-13〜14
- 対象: 実験1（`../exp1/libero_spatial_n5/`）、実験2（`../exp2/hidden_cabinet_n20/`）と、本フォルダの切り分けの評価
- 共通条件は実験1・2 と同じ（`allenai/MolmoAct2-LIBERO`、float32、シード 1000、`num_steps_wait=50`）

## 結論

1. **追加学習なしでは、SG をテキストで加えても効果はない。** 標準タスク（実験1）では成功率が上がらず内容によらずやや下がり、隠れた物体のタスク（実験2）ではどの条件も 0/20
2. **MolmoAct2 は、見えている物体については指示文の場所の指定を使う。見えていない物体を探しには行かない。** 隠れたボウルのタスクでは、20 回中 19 回、見えている方のボウルを皿に置いた
3. **隠れたボウルは物理的には掴める**（スクリプト制御で 50/50）。実験2 の失敗はタスクの難しさではなく、ポリシーの行動の問題
4. SG を使わせるには、隠れた物体を取りに行く動作を含むデータでの追加学習が必要（Phase 5）

## 1. 指示文の言語をどこまで使っているか（プロンプト条件 L0・L1）

実験1 の条件に、指示文そのものを変える 2 条件を加えた（`settings.PROMPT_CONDITIONS`）。

| 条件 | 指示文 |
|---|---|
| L0 | 場所の指定を除く（"pick up the black bowl and place it on the plate"。libero_spatial 形式の指示文のみ） |
| L1 | 同じスイートの別タスク（タスク ID を 5 ずらす）の指示文に置き換える |

| 評価 | 成功率 | 比較 |
|---|---|---|
| libero_spatial × L0 | 88%（44/50） | A（元の指示文）96% |
| libero_spatial × L1 | 76%（38/50） | 同上 |
| libero_goal × L1（陽性対照） | 0%（0/50） | ベースライン 98% |
| 隠れシーン × L1（task 0 に "next to"、task 1 に "behind" の指示） | task 0 0/20、task 1 20/20 | A と同じ |

各エピソードで何をどこに置いたか（終了時の SG で新しくできた on / in。`scripts/summarize_results.py`）は `language/*/outcomes.md`。

- **libero_goal × L1**: 同じシーンで別タスクの指示を与えると、ほぼ毎回その指示どおりに動く（例: 「ボウルをコンロへ」→ 5 回ともボウルをコンロに置く）。動詞・目的地の指示はよく従う
- **libero_spatial × L0**: 場所の指定がなくても 88% 成功する。多くのシーンで、元のタスクで掴むボウル（ボウル 1）を選ぶ。指定がないと、task 3・6・9 で他方のボウルを置くことがある（計 6 回）
- **libero_spatial × L1**: 他方のボウルを特定する指示文では、そちらを選ぶ。task 1 のシーンで "next to the cookie box" と指示すると、5 回ともクッキーの箱の隣のボウル 2 を皿に置いた（このためタスクとしては 0/5）。指示文がシーンに合わない場合（"on the ramekin" と指示したが、ラメキンの上にボウルがない など）は、元の対象を選ぶ
- まとめると、MolmoAct2 は「見えている候補の中から、指示文の場所の指定に合うものを選ぶ」ことはできる。候補が見えていなければ、見えている物体の中から選ぶ

## 2. 失敗の種類

| 実験 | 失敗の内容 |
|---|---|
| 実験1（標準タスク、SG あり） | 対象とは違うボウルを掴む失敗はなかった。正しい対象の近くまで行って止まる・置き終わらずに時間切れになる（動画で確認） |
| 実験2 の隠れあり（task 0、条件 A を取り直したもの） | 20 回中 19 回、見えている方のボウル（ボウル 2）を皿に置いた（ラメキンも動かしたのが 2 回）。1 回はラメキンを皿に置いた。キャビネットの方へ向かったことは一度もない |
| 実験2 の隠れあり（L1: "next to the wooden cabinet"） | 17 回ボウル 2、3 回ラメキンを皿に置いた |

実験2 の条件 B1〜D は終了時の SG を記録する前に実行したため自動の分類はないが、最後のフレームを見る限り A と同じ傾向（`../exp2/hidden_cabinet_n20/final_frames_hidden.png`）。

## 3. 隠れたボウルは掴めるか

`scripted_hidden_cabinet/README.md`。正解の位置へ手先を動かすスクリプト制御で、初期状態 50 件すべてで成功した（266〜279 ステップ、上限 300）。キャビネットを避けるため、手前側を回る経由点が必要。

## 4. 原因の切り分け

| 仮説 | 判定 | 根拠 |
|---|---|---|
| LIBERO の指示文に過学習していて、プロンプトの変化を無視する | 部分的に否定 | libero_goal では別タスクの指示に従い、libero_spatial でも場所の指定で他方のボウルを選べる。ただし SG のような長い追加テキストの内容は使わない（実験1 の C・D が B1 と同程度） |
| 見えない物体を取りに行く動作が学習されていない | 支持 | 隠れシーンでは指示文・SG によらず、見えている物体へ向かう。LIBERO の学習データには隠れた物体を探すデモがない |
| タスクが物理的にできない | 否定 | スクリプト制御で 50/50 |

## 5. 追加学習ありの計画（案、ユーザーと相談して決める）

- 学習データ
  - 隠れた物体: スクリプト制御（現在は `scripts/generate_demos.py`）を広げて、隠れたボウルを取り出して置くデモを自動で作る（配置・遮る物体を変えて多数）。見える版のデモも混ぜ、SG なしでも解けるタスクを忘れないようにする
  - 実験1 用: LIBERO の公式デモ（libero_spatial など）の指示文に、デモ開始時の状態から作った SG を付ける
- SG の付け方: 推論時と同じ `compose_prompt`（B1〜B3）で学習時の指示文を作る。対照として、同じデータを SG なしで学習したモデルも作り、「SG の有無」の効果を切り分ける
- 学習方法: LeRobot の MolmoAct2 は VLM 部分を LoRA で学習できる（`train_mode_vlm="lora"`、既定）。RTX 5090（32GB）で学習できるかは、推論時の VRAM ピークが約 26GB のため、bf16 や勾配チェックポイントを含めて事前に確かめる必要がある
- 実験3（SG エンコーダー）: テキストでの結果を見てから構成を決める
