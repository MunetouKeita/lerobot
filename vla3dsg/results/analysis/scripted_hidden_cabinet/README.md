# キャビネットの裏のボウルは物理的に掴めるか（スクリプト制御）

- 日時: 2026-10-13
- 実行: `uv run python vla3dsg/scripts/scripted_pick_place.py --name analysis/scripted_hidden_cabinet --suite vla3dsg_hidden --task-id 0 --target akita_black_bowl_1 --dest plate_1 --via=-0.25,0.0`（当時のスクリプト。現在は `generate_demos.py --check --name <名前> --suite vla3dsg_hidden --task-ids 0` で同じ確認ができる。2026-10-14 に統合後のスクリプトで 2 回確認した結果は 48/50・49/50。失敗はどちらも掴む前に手先が止まり、指令の上限 600 ステップに達したもの。同じ初期状態でも成否が変わることがあり、シミュレータに完全には再現しない要素がある）
- 対象: 実験2 の隠れありタスク（`vla3dsg_hidden` task 0）の初期状態 50 件すべて
- 方法: シミュレータの正解の位置へ手先を動かす（姿勢は初期のまま、位置の誤差に比例した指令）。ボウルのロボット側の縁を上から掴み、持ち上げ、キャビネットを避ける経由点（手前側、高さ +0.25 m）を通って皿の上へ運び、放す。制御の設定は `conditions.json`（`settings.SCRIPTED_*`）
- 動画: `videos/episode_{0,1,2}.mp4`（git 管理外）

## 結果

| 項目 | 結果 |
|---|---|
| 成功（BDDL の成功条件: ボウル 1 が皿の上） | 50/50 |
| 成功までのステップ数（物体が落ち着くまでの 50 ステップを除く） | 266〜279（評価の上限は 300） |
| 持ち上げた高さ | 0.127〜0.128 m |

- キャビネットの裏（agentview から見てキャビネットの奥＝ロボット側）のボウルは、ロボットから十分に届き、掴んで皿まで運べる。実験2 の 0/20 は、タスクが物理的にできないためではない
- 皿へまっすぐ運ぶとキャビネットに引っかかるため、手前側を回る経由点が必要だった（試行時、経由点なしでは 10 件中 4 件しか成功しなかった）
- 腕がボウルの上に来ると、手首カメラにボウルが映る。探しに行けば画像からも見つけられる配置である
- このスクリプト制御は、追加学習で隠れた物体のデモを作る候補になる（ただし動作は機械的で、LIBERO の人によるデモより遅い）
