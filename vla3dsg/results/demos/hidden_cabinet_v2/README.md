## 方法

- タスク: 実験2 の自作スイート `vla3dsg_hidden` の task 0（キャビネットの裏に隠れたボウル）と task 1（キャビネットの横の見えるボウル）。成功条件はどちらも「ボウル 1 が皿の上」
- 配置: BDDL の配置範囲から、評価の初期状態（シード 0〜）とは別のシード（100000〜）でサンプリング。押し出し・転倒した配置は除く
- 動作: 評価と同じく初期状態を設定して 50 ステップ待ったあと、スクリプト制御（`vla3dsg/demos/scripted.py`、設定は `settings.SCRIPTED_*`・`DEMO_*`）で掴んで置く
  - 移動: 位置の誤差に比例させ、3 軸まとめた速さの上限 0.8、1 ステップの変化量の上限 0.1（加速・減速をなめらかにする）。掴む・置く高さの 3cm 上からは速さ 0.3 でゆっくり下ろす
  - 回転: 手先の向きを保つように補正する。掴む前に鉛直軸まわりに回す（task 0 は 90°）
  - 揺らぎ: 移動・回転の指令に、ゆっくり変化する小さな揺らぎ（標準偏差 0.02・0.01）を加え、経由点を水平に ±2cm ずらす
  - 目標に届かずに手先が止まったら（10 ステップで 2mm 未満）、次の動作へ進む
  - task 0: ロボット側の縁を、手先を 90° 回して指が縁の壁を挟む向きで掴み、キャビネットを避ける経由点（手前側）を通って皿へ
  - task 1: キャビネットと反対側（+y 側）の縁を掴む
- 成功し、評価の最大ステップ数（300）に収まったエピソードだけを保存
- 形式は `lerobot/libero` と同じ（画像 256×256 を 180° 回転、状態 8 次元 = 手先の位置・軸角・グリッパー、動作 7 次元、fps 10 の表記）。指示文はタスクの元の指示文（SG なし）

## v1 からの変更と理由

1. **掴むときに押し続けない**: v1 の task 0 は、ロボット側（x 方向）の縁を掴もうとしていたが、開いた指は y 方向に並ぶため、片方の指が縁の上に乗って下りられず、目標に届くまで（1 回の移動の上限 150 ステップ）押し続けていた。エピソードの約半分が止まった状態だった。手先を 90° 回して指が縁の壁を挟む向きにし、さらに止まったら次の動作へ進むようにした
   - y 方向の縁を掴む方法も試したが、腕の前腕（`robot0_link5`）がキャビネットに当たって下りられなかった
2. **なめらかに動かす**: v1 は 1 軸ずつ上限で動いて急に切り替わっていた。3 軸まとめて速さを制限し、指令の変化量も制限した。速さを制限したため、勢いが残って掴み損ねないよう、掴む・置く直前だけゆっくり下ろす
3. **回転の指令を入れる**: v1 は回転の指令が常に 0 だった。手先の向きを保つ補正と小さな揺らぎで、公式デモと同程度の大きさになった

## 残っている違い

- 公式デモより長い（191・142 ステップ。公式は 100 ステップ）。移動の速さの上限を 0.8 にしており、公式デモのように上限（0.94）付近まで速く動くことがないため。評価の最大ステップ数（300）には収まる
- task 0 は、掴む前に手先を 90° 回すため、最初に大きな回転の指令（rz が最大 0.94 付近）が出る。公式デモにはない動き
- 止まっている割合（6%・10%）は、グリッパーを閉じる・開くあいだ動かないため（各 15 ステップ）。公式デモは動きながら開閉する
