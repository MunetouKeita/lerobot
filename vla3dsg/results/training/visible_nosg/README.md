# 追加学習（SG なし）: 見えるボウルを広い範囲に置いたデモで、遠いボウルを掴めるようになるか

- 日時: 2026-10-29 15:27〜21:30（このPC、RTX 5090。学習 5 時間 13 分、1 ステップ約 1.55 秒、GPU メモリ 29.3GB）
- 目的: SG は使わずに、見えるボウルを広い範囲に置いたデモで追加学習し、学習前に失敗していた遠いボウル（2-3）を掴めるようになるか（そもそも学習が効くか）を確かめる
- 実行: `setsid nohup vla3dsg/results/training/visible_nosg/run.sh`（学習前の評価 → 学習 → 学習後の評価 → `results.md`。各工程の開始・終了は `status.log`）
- データ: `data/goal_train/` のうち、正解のボウルが見える 2 シーン（task 0 wide・task 3 decoy_visible、各 50 本、16,222 フレーム）。隠れたボウルの 2 シーンは SG なしでは解けないため使わない。decoy_visible（ボウル2個,見えるボウル=ランダム,見える方が正解）はおとりが正面のカメラから見えないため、SG なしでは wide とほぼ同じデータになる（手首カメラに映るかは未確認）。公式デモは混ぜない
- 学習: `allenai/MolmoAct2-LIBERO` から LoRA（VLM、rank 64）＋アクションエキスパートは全パラメータ。有効バッチ 32（8 × 勾配累積 4）、12,000 ステップ ＝ 更新 3,000 回（データ約 6 周）。学習率は既定（VLM 1e-5、アクションエキスパート 5e-5）で、800 ステップ（更新 200 回）で上げ、12,000 ステップで 1e-6 まで下げる（LeRobot のステップと学習率の予定はマイクロバッチで数える）。チェックポイントは `outputs/train/visible_nosg/`（git 管理外）
- 評価: 各 20 エピソード、公式の指示文のみ。学習用シーンは評価用の初期状態（学習のデモとは別の配置）。遠いボウルは `vla3dsg_goal_layout` の task 1・2・5、標準は `vla3dsg_goal` の task 0。学習後のチェックポイントは `run_eval.py --policy-path`（手首カメラの名前を学習データに合わせて `image2` にする）

## 読み取れること

- **学習が効き、遠いボウルを掴めるようになった。** 学習のデモとは別の配置（`vla3dsg_goal_layout` の遠いボウル 3 シーン）でも 0〜5% → 50〜90%。ボウルの位置は学習用シーンの配置範囲（x −0.22〜0.16）の中だが、皿の隣（手前左へ（固定）・遠くへ）は、学習用シーンでは物体どうしが近すぎるとして除いた配置
- 標準のシーンは下がらない（95% → 100%）。公式デモを混ぜなくても、少なくともこのタスクは忘れていない（ほかの libero_goal のタスクは未評価）
- 更新 1,000 回と 3,000 回で差はほぼない（合計 96/120 と 93/120）。このデータ量では 1,000 回（約 2 周、約 1.7 時間）で十分な可能性がある
- 失敗の多くは何も置かずに時間切れ（3,000 回の遠いボウルで 19 件中 16 件）。学習前の失敗は、ボウルを皿の縁に置く・クリームチーズを置くなどばらばらだったのと違う（失敗の中身は下の「失敗の確認」）
- 「ボウル1個,遠く」（ロボットから 0.37m、x 0.15 で配置範囲の端）は 50〜55% にとどまる
- スクリプト制御のデモは公式より遅い（3-5）が、遠いボウルの 3 シーンの最大 300 ステップには収まっている

## 失敗の確認（更新 3,000 回の遠いボウル 3 シーン、失敗 19 本）

各失敗動画の最後のコマで、手首カメラに映る指の開き具合と手先の位置を見た（成功した回と比べた）。

| 失敗の種類 | 本数（手前左へ（固定）／遠くへ／遠く・皿から離して） | 様子 |
|---|---|---|
| 開いたまま、ボウルの真上で止まる | 8（0／7／1） | 手先がボウルの縁ではなく中心の上に来て、高さを上下させながら下りない。手先を回していない回もある |
| 開いたまま、皿の上で止まる | 6（5／1／0） | ボウルの近くまで行った後、掴まずに隣の皿の上へ動いて止まる |
| 空中でグリッパーを閉じる | 5（2／2／1） | ボウルの上や横で、何も挟まずに閉じ、開き直さずに浮いたまま止まる |

- 成功した回は、ボウルが手首カメラの片側に寄る（縁を挟む位置に手先が来る）。失敗した回は、ボウルが手首カメラの中央に来る（手先がボウルの中心の上にある）ことが多い
- 掴み損ねた後に開き直して掴み直す動きは、どの失敗にもない。スクリプト制御のデモに立て直す動きがない（既知の問題）ことと合う
- 推測: 学習用シーンでは、遠い左手前のボウルはロボット側の縁（170〜190°）、ロボット寄りのボウルは 0〜150° の縁を掴むため、ボウルの位置で掴む点が大きく変わる。配置範囲の端や皿の隣では、どちらの縁を掴むかが決まらず、間（中心の上）で迷っている可能性がある（動作の記録はとっていないため、未検証）
