# progress_management.md — VLA×3DSG 進捗管理

最終更新: 2026-11-10

研究の概要・環境・リポジトリ構成は、リポジトリのルートの `CLAUDE.md` を参照。各実験の詳しい設定・結果・うまくいかなかった方法は `experiments.md`（節の番号は共通）。本ファイルのパスは、特に断りがない限り `vla3dsg/` からの相対パス。

## 研究目的

VLA※1 の言語指示に 3D シーングラフ（SG※2）の情報を加え、カメラ画像だけでは見えない（隠れた）物体も扱えるようにする。まずシミュレーション（LIBERO）上で、テーブルの上の隠れた物体を対象に検証する。

## 研究の組み立て（実験の位置づけ）

主張は「SG は指示文の位置関係より良い」ではなく、次の 2 つに置く（2026-11-10、ゼミでの指摘を受けて決定）。

1. 人は対象の位置関係まで言わないことが多い。ロボット側の 3DSG がその情報を補えば、VLA は人が関係を書いた場合と同じように対象を見分けられる
2. 画像に写らない（隠れた）物体は、人も場所を知らないことが多く、画像にも手がかりがない。3DSG だけがその情報を持つ

見える物体では、情報の量は「SG ＝ 人が書いた関係の指示」で同じになる。そのため「元のモデルでも関係の指示ができる」という指摘に対しては、両者を同じ表に並べて答える。

| 段階 | 内容 | 示すこと | 環境 |
|---|---|---|---|
| 段階 1（5 節） | 目の前の同じ種類の 2 つの物体を、SG で見分ける | SG の関係が、人の書いた関係と同じように使われる（パイプラインが成り立つ） | libero_spatial の配置で、正解を入れ替えた対（`vla3dsg_spatial`） |
| 段階 2（4 節） | 隠れた物体を SG で見つけて掴む | SG にしかできないこと。元のモデルは、場所を書いた指示文でも隠れたボウルを掴めない（2-2 の sg_command で 0%） | libero_goal・KITCHEN_SCENE4 の隠れたシーン（4-2〜4-4）。段階 1 の結果を見て、libero_spatial に寄せるかを決める |
| 段階 3（未着手） | SG を知覚から作る、移動ロボット・実機 | 人が何も言わなくてよい | UMI 型の教示デバイス・実機 |

比較表には、必ず次の 3 つの指示文の条件を並べる。

| 条件 | 意味 |
|---|---|
| 人が書いた関係の指示文（公式の言い方） | 情報量が同じ条件の上限 |
| 関係を外した指示文（SG なし） | 人が場所を言わない場合。見分けられなければ当て推量（約 50%） |
| 関係を外した指示文＋SG | 3DSG で補った場合 |

- 段階 1 の学習前の評価で、正解を入れ替えたタスク（b2）を公式の言い方で解けるかを最初に確かめる。解けなければ、元のモデルの 96% は配置の記憶で、関係の指示は読めていない（言葉より画像に頼るという報告: LIBERO-Plus https://arxiv.org/abs/2510.13626 、配置を固定して指示文だけを変える LangGap https://arxiv.org/html/2603.00592 。LangGap は対の発想が近い先行研究として引用する）。解ければ、関係を外した指示文＋SG が人の書いた関係に追いつくかを示す
- 学習方法は模倣学習（BC）のままとし、比べる条件は SG の有無だけにする。LeRobot のほかの学習方法（RA-BC・DAgger・HIL-SERL）の調査結果と判断は「現在の設計方針」の表

| チェックポイント | 2,000 ステップ（更新 500 回）ごとに保存し、評価が済んだものは消す | 学習の途中の変化を見るため（ゼミでの指摘）。1 つ 18GB あり、ディスクが足りなくなるため | 2026-11-10 |

## 実験の結論（詳細は `experiments.md`）

| 節 | 実験（結果） | 結論 |
|---|---|---|
| 1-1〜1-3 | ベースライン（`results/baseline/`） | 全 40 タスク × 5 で 97.0%（報告値 97.2%）。推論 189ms・GPU 約 26GB。報告値を再現でき、このPCで評価できる |
| 2-1 | SG の形式の比較（`results/zeroshot/formats.md`） | 形式（三つ組・JSON・自然文）による差はない。誤った SG でも同程度で、中身は使われていない。長い SG と同じ長さの無関係な文はどちらも 0% で、下がるのは長さによる |
| 2-2 | 4 シーン × 5 条件（`results/zeroshot/comparison.md`） | 標準 95〜100%、ボウル1個,4物体シャッフル 0〜55%（付け足すと上がるが中身によらない）、隠れた 2 シーンはすべて 0%（見えるおとりやクリームチーズを置く）。追加学習なしでは SG の場所の情報は使われない |
| 2-3 | 一方の物体だけを動かした 7 シーン（`results/zeroshot/layout_check/`） | ボウルが学習時よりロボットから遠いと 0〜5%（皿の位置は関係ない）。公式データではこのシーンのボウルはいつも同じ場所にある |
| 3-1 | 学習が回るか（`results/training/train_check/`） | このPCで LoRA※7 の学習ができる（バッチ 8、29.7GB）。余裕は約 3GB |
| 3-2・3-3 | スクリプト制御とランダム化（`results/demos/check_goal/`・`check_goal_random/`） | `vla3dsg_goal` の 4 シーンでできる（9〜10/10）。掴み方を決めた理由と失敗した方法は experiments.md |
| 3-4 | 学習用のシーン（`results/demos/check_goal_train/`） | 4 シーンとも 10/10。見えるボウルの位置は 3 つのまとまりになり、一様には散らばらない |
| 3-5 | 学習用のデモの生成（`results/demos/goal_train/`） | 200 本（47,562 フレーム）。見えるボウルのデモは公式の約 1.7 倍長く、動きが遅い |
| 4-1 | SG なしの追加学習（`results/training/visible_nosg/`） | 見えるボウルのデモ 100 本で、遠いボウルが 2/60 → 41〜44/60、標準は 19 → 20/20。更新 1,000 回と 3,000 回で差はほぼない。失敗は掴まずに止まる時間切れ |
| 4-2 | 4 シーンで SG なし／あり（`results/training/sg_vs_nosg/`） | おとりのあるシーンで SG が効く（隠れた方が正解: 30〜35% → 85%、見える方が正解: 60% → 90%）。隠れは SG なしでも 95〜100%（隠し場所が 1 か所）。標準は 95% → 40%（SG なし）・65%（SG あり）に下がる（ワインラックの裏へ行く癖） |
| 4-3 | 見えるボウルのデモの追加＋公式デモ（`results/training/balanced_sg_vs_nosg/`） | 癖はほぼなくなる（標準 SG なし 40% → 85%、SG あり 65% → 85%）。学習用シーンのおとりありでは SG の効果が保たれる（SG なし 50%、SG あり 78%）。2-2 のおとりあり（おとりが標準の位置）は SG ありでも 85% → 30%（見えるおとりを置く）。正解を入れ替えたシーン（標準の位置が正解）は 95% のままで、標準の配置では SG に関係なく標準の位置を掴む |

## 既知の問題

| 問題 | 影響 | 対処 |
|---|---|---|
| `lerobot-eval` は、LeRobot 形式の `MolmoAct2-LIBERO-LeRobot` を読めない・`num_steps_wait` を指定できない（既定 10）・動画が先頭 10 本だけで終了フレームが欠け 80fps で保存される | 報告値と条件がずれる、失敗の動画が残らない | 元の HF チェックポイント、環境タイプ `libero_vla3dsg`、`visualization/rollout_video.py` で対処済み |
| スクリプト制御が、同じ初期状態でも時々失敗する（掴む前に手先が止まる。46〜50/50） | デモの生成で一部が除外される | 失敗したエピソードは保存しない |
| 掴む点を 5mm ずらすだけで、半分ほど掴み損ねる | 掴む点のばらつきを持たせられない | 掴む点はずらさず、掴む向き・経路・速さでばらつきを出す。動きの多様性が足りない可能性は残る |
| スクリプト制御のデモには、ずれから立て直す動きがない | 学習したポリシーが、少しずれると立て直せない可能性 | 未対応（候補: 実行時だけ動きを乱し、正しい動作を記録する方法、公式デモを混ぜる） |
| スクリプト制御のデモは公式より約 1.7 倍長く、移動の指令が上限に達しない（3-5） | 学習したポリシーが遅くなり、最大ステップ数に収まらない可能性 | 4-1 の評価（最大 300 ステップ）では収まった。失敗の多くは掴まずに止まる時間切れで、遅さとの関係は未検証 |
| robosuite はエピソード長の上限（1000）を超えると動作の指令をエラーにするが、LIBERO は終了フラグを成功判定で上書きするため上限に達したことがわからない | 長引いたスクリプト制御が途中で止まる | 1 エピソードの指令を 600 ステップで打ち切る |
| ボウルを学習時よりロボットから遠い位置に置くと、ほぼ成功しない（0〜5%。2-3） | 配置を変えたシーンでは、SG と関係なく成功率が下がる | 見えるボウルを広い範囲に置いたデモで追加学習すると 50〜90% に上がる（4-1） |
| 保存した初期状態を読み込んでも、保存したときの動きが完全には再現しない（物体が重なった初期状態では、弾かれてテーブルの外へ落ちる。1 つの環境で続けて読み込むと、まれに直前のエピソードの影響で結果が変わる。200 件中 1 件） | 初期状態の確認をすり抜ける | `make_custom_task.py --min-distance` で、評価と同じく読み込んで待ってから確かめる（デモの配置にも適用）。デモの SG は開始時の実際の状態から作る |
| LIBERO の環境を作るときの配置のサンプリングは乱数が固定されず、配置範囲が他の物体と重なるタスクではまれに失敗する（`RandomizationError`） | 環境の作成で止まる | 作り直す（`custom_task_builder.make_env`、`settings.ENV_CREATE_RETRIES`）。`lerobot-eval` で評価する場合にも起きうる |
| 段階 1 の追加学習（5-2）で、掴んで置く動作が学習前より悪くなる（時間切れなど、それ以外の失敗が 2〜20 → 45〜88/200） | SG の効果は出るが、合計で学習前のモデル＋公式の言い方を下回る | 未対応（「次に行うこと」の候補） |
| 学習サーバの GPU は他のユーザーが使用率 100% 近くで使っていることが多い | 1 枚あたり 5090 の 1/4 程度の速さしか出ない | 使う前に空きを確かめる |
| このPCの GPU を他のプロセス（ollama）が使っている | 評価が動かない（メモリ不足） | 止めずに、空くまで待つか学習サーバで評価する |

## 用語の補足

- ※1 VLA（Vision-Language-Action model）: 画像と言語の指示から、ロボットの動作を出力するモデル
- ※2 SG（シーングラフ）: 物体をノード、物体どうしの関係（上にある、裏にある など）をエッジとしたグラフ。本研究では三つ組 (主語, 関係, 相手) の列で表す
- ※3 agentview: LIBERO の主カメラ。テーブルの反対側からロボットの方を向いて見る。ほかに手首カメラがある
- ※4 おとり: 対象と同じ種類の別の物体（黒いボウル）。指示文や SG で区別しないと、どちらを取るべきかわからない
- ※5 スクリプト制御: シミュレータから物体の正確な位置を読み、決めた手順で手先を動かす制御。学習は使わない
- ※6 エピソード: 1 回の試行（初期配置から、成功するか最大ステップ数に達するまで）
- ※7 LoRA: モデルの重みは固定し、小さな追加の重みだけを学習する方法。少ない GPU メモリで学習できる
- ※8 マイクロバッチ: 1 回に GPU で計算するサンプルのまとまり。いくつか分の勾配をためてから重みを更新する（勾配累積）と、大きなバッチと同じ効果になる
- ※9 DAgger: 学習したポリシーを動かし、うまくいかない場面で専門家（人やスクリプト）が正しい動作を示して、それを教師データに足して学び直す方法
